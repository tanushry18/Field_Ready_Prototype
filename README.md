# Field-Ready Prototype — RaceGuard

RaceGuard is a field-ready prototype for testing multiplayer session-state backends under retries, duplicate requests, concurrent races, delayed events, out-of-order events, and transaction failures.

The prototype replays the same deterministic workload through two processing paths:

- **Unsafe Baseline:** Deliberately allows check-then-insert race conditions and stale-state regression.
- **RaceGuard:** Models atomic idempotency-key claims, transaction boundaries, version checks, trace capture, rollback, and replay-safe responses.

The dashboard reports measured results generated by the experiment engine rather than using hardcoded KPI values.

---

## Features

- Deterministic workload generation using a configurable seed
- Baseline vs. RaceGuard comparison
- Idempotency-key handling
- Duplicate-request detection
- Retry simulation
- Concurrent request simulation
- Delayed and out-of-order event simulation
- Transaction-failure injection
- Request and transaction tracing
- Session version checking
- Rollback and recovery tracking
- Latency and throughput measurement
- Failure analysis
- JSON experiment export
- Docker support
- Responsive dashboard

---

## Technology Stack

- **Frontend:** React + Vite
- **Backend:** Node.js + Express
- **API:** tRPC
- **Language:** TypeScript
- **Development:** pnpm
- **Containerization:** Docker
- **Storage:** In-process experiment store for the prototype

The managed WebDev scaffold exposes the application as a single Node.js process. Therefore, the prototype uses React + Vite on the client and Express + tRPC on the server rather than a separate Python service.

The processing API is kept behind typed tRPC procedures so that the UI and experiment engine share a consistent API contract.
